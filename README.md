# ربات خبریوم | Khabarioom

ربات گردآوری خبر برای کانال تلگرام [@khabarioom](https://t.me/khabarioom).

## وضعیت پروژه (اکتبر ۲۰۲۶)

- ✅ نصب تمیز وابستگی‌ها روی Python 3.12 و 3.13 و 3.14 آزموده شده است؛ همهٔ پکیج‌های pin‌شده (از جمله PyYAML 6.0.3 و lxml 6.0.1) wheel آماده برای این نسخه‌ها دارند و نیازی به کامپایلر (Visual C++ Build Tools) نیست.
- ✅ بستهٔ `tzdata` در requirements هست؛ خطای `ZoneInfoNotFoundError: 'Asia/Tehran'` روی Windows برطرف است.
- ✅ ۷۸ تست واحد آفلاین (pytest) برای تنظیمات، دیتابیس، منابع، کپشن، انتشار، دستورات و گزارش‌های روزانه می‌گذرد و در GitHub Actions روی Python 3.12/3.13/3.14 اجرا می‌شود.
- ⚠️ هنوز آزموده نشده (نیازمند توکن/دسترسی واقعی): ارسال واقعی به کانال تلگرام، سلامت لحظه‌ای RSSها، و استقرار production. هیچ ادعایی دربارهٔ این موارد مطرح نیست.

## قابلیت‌های فعلی

- دریافت خبر از منابع RSS، صفحات وب و کانال‌های عمومی تلگرام که در `sources.yaml` تنظیم شده‌اند؛ خطای هر منبع جداگانه ثبت می‌شود و چرخه را متوقف نمی‌کند.
- بررسی چرخه‌ای منابع (پیش‌فرض هر ۳۰ دقیقه با `FETCH_INTERVAL_MINUTES`)؛ با `MAX_SOURCES_PER_CYCLE` منابع به‌صورت چرخشی (round-robin) در هر چرخه انتخاب می‌شوند.
- جلوگیری از انتشار دوباره با SQLite و نرمال‌سازی URL (حذف پارامترهای ردیابی مثل `utm_*`، یکسان‌سازی دامنه/اسلش) تا خبرهای با URL معادل تکراری منتشر نشوند.
- استخراج متن (trafilatura) و تصویر (og:image / media)؛ اگر ارسال عکس شکست بخورد، به‌صورت متن ارسال می‌شود.
- کپشن HTML با escape کامل عنوان/متن/لینک؛ پیام‌های طولانی فقط در مرز فاصله/خط جدید شکسته می‌شوند تا HTML خراب نشود و هیچ بخشی گم نشود.
- درج دو هشتگ و امضای `@khabarioom`؛ لینک منبع به‌صورت پیش‌فرض خاموش است (`ADD_SOURCE_LINK=false`).
- دستورات مدیریتی فقط برای `ADMIN_USER_IDS`: `/status`، `/sources`، `/search کلمه` و `/test`.
- ساعات سکوت ۰۱:۰۰ تا ۰۷:۰۰ تهران برای خبرهای غیر اولویت‌دار (خبرهای عادی بعد از ساعات سکوت در چرخهٔ بعد منتشر می‌شوند). تشخیص خبر اولویت‌دار فقط کلیدواژه‌ای است و راستی‌آزمایی مستقل نیست.
- پین خبرهای کلیدواژه‌ای با حداقل فاصلهٔ `PIN_COOLDOWN_HOURS` ساعت؛ خطای پین (مثلاً نبود دسترسی) بدون توقف ربات ثبت می‌شود.
- پیام معرفی کانال بعد از هر `PROMO_EVERY_N_POSTS` خبر.
- رکورد خبر بلافاصله پس از موفقیت بخش اول پیام ذخیره می‌شود تا شکست بخش‌های بعدی باعث انتشار تکراری نشود.
- گزارش‌های روزانه: آب‌وهوای تهران ۰۷:۱۵ (Open-Meteo)، بازار ۰۸:۰۰ (نفت WTI از Yahoo Finance؛ قیمت‌های دلار/طلا/سکه/بیت‌کوین فقط با `ARZHAAM_API_KEY`)، اندیشهٔ روز ۰۹:۰۰ (متن‌ها برداشت آزاد هستند، نه نقل‌قول مستقیم).
- پشتیبانی از Docker و Railway.

## اجرای محلی

نیازمند Python 3.12 یا جدیدتر (3.13 و 3.14 نیز آزموده شده‌اند):

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
# فایل .env را باز کنید و TELEGRAM_BOT_TOKEN و ADMIN_USER_IDS را وارد کنید.
python main.py
```

در Linux/macOS از `source .venv/bin/activate` استفاده کنید. اگر `py` در دسترس نیست، از `python -m venv .venv` استفاده کنید.

اگر قبلاً نصب ناقصی داشته‌اید (مثلاً PyYAML قدیمی از سورس build شده بود)، یک محیط مجازی تمیز بسازید و همهٔ requirements را یک‌جا نصب کنید؛ نسخه‌های pin‌شدهٔ فعلی همه wheel دارند.

## ارسال یک خبر برای آزمایش (اختیاری)

به‌جای اجرای دائمی ربات می‌توانید یک خبر تازه را یک‌جا به کانال بفرستید (نیازمند `.env` با توکن واقعی):

```powershell
python tools/send_one_news.py             # ارسال اولین خبر تازهٔ منتشرنشده
python tools/send_one_news.py --dry-run   # فقط پیش‌نمایش کپشن، بدون ارسال
python tools/send_one_news.py --force     # نادیده گرفتن ساعات سکوت ۰۱–۰۷ تهران
```

## اجرای تست‌ها

```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
```

تست‌ها کاملاً آفلاین‌اند (HTTP و تلگرام شبیه‌سازی می‌شوند) و به توکن یا اینترنت نیاز ندارند.

## متغیرهای ضروری

- `TELEGRAM_BOT_TOKEN`: توکن BotFather؛ فقط در محیط اجرا/.env محلی نگه‌داری شود و هرگز در Git ثبت نشود.
- `CHANNEL_ID`: پیش‌فرض `@khabarioom`.
- `ADMIN_USER_IDS`: آیدی عددی مدیران، برای دستورات مدیریتی.
- `DATABASE_PATH`: مسیر دیتابیس SQLite (پیش‌فرض `data/khabarioom.sqlite3`)؛ پوشه به‌صورت خودکار ساخته می‌شود. در میزبانی ابری برای حفظ داده‌ها Volume پایدار تنظیم کنید.
- `SOURCES_FILE`: اختیاری؛ مسیر فایل منابع (پیش‌فرض `sources.yaml` کنار `main.py`).

تنظیمات کامل با توضیح در `.env.example` آمده است.

## اجرای دائمی (وقتی سیستم خاموش است)

ربات برای کار ۲۴/۷ باید روی سرور اجرا شود، نه کامپیوتر شخصی. سه راه آماده است:

- **Railway** (پیشنهادی): از ریپو Deploy کنید؛ `Dockerfile` و `railway.toml` آماده‌اند. برای SQLite یک Volume پایدار متصل کنید و `DATABASE_PATH` را داخل همان Volume بگذارید. توکن را فقط در Variables/Secrets میزبان بنویسید.
- **VPS با systemd**: فایل آمادهٔ `deploy/khabarioom.service` با `Restart=always`.
- **GitHub Actions** (رایگان، محدود): قالب‌های آماده در `deploy/github-actions/` — خبر هر ۳۰ دقیقه و سه گزارش روزانه در ساعت تهران (UTC+3:30).

جزئیات گام‌به‌گام هر سه روش + چک‌لیست پس از استقرار: **`DEPLOY_FA.md`**.

## CI

`.github/workflows/python-checks.yml` روی هر push/PR برای Python 3.12، 3.13 و 3.14 اجرا می‌شود: نصب کامل requirements، کامپایل همهٔ ماژول‌ها، بررسی import، تأیید دسترسی منطقهٔ زمانی `Asia/Tehran` و اجرای تست‌های واحد.

## نکتهٔ مهم دربارهٔ متن خبر

تنظیم پیش‌فرض کپی کامل خبر خاموش است (`COPY_FULL_ARTICLE=false`) و فقط خلاصهٔ محدودی از متن منتشر می‌شود. خروجی فعلی سامانهٔ هوش مصنوعی برای بازنویسی و راستی‌آزمایی چندمنبعی ندارد؛ پیش از انتشار عمومی پایدار باید صحت تک‌تک RSSها و رفتار استخراج متن با تست واقعی شبکه بررسی شود. تصاویر و متن ممکن است به دلیل محدودیت یا تغییر ساختار سایت در دسترس نباشند.
